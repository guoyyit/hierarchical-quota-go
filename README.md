# hierarchical-quota-go

分层资源配额控制：将工作负载组织为可嵌套的配额组，支持组内与父子组之间
传递额度、跨组借用余量与故障恢复（原子重配置 + 重启恢复）。

## 核心概念

### 配额树与继承

- 配置为一棵树：恰好一个根组，其余组通过 `parent` 挂接，不允许成环。
- 子组按 `share_ratio`（取值 `(0,1]`）从父组的**有效额度**中分得份额：
  `有效硬顶 = min(自身 hard, 父组有效 hard × share_ratio)`，
  未配置的资源整体继承父组份额；软顶同理且不超过硬顶。
- 父组上调/下调额度后，子组的有效额度在重配置提交的同一时刻整体收敛到新预算。
- 任一时刻生效的限额是某个**已提交配置的完整快照**：配置以原子指针整体切换，
  进行中的消耗判定始终与某一个单一版本保持一致，不存在半更新或字段级混合。

### 硬上限与软上限

- **软上限**：水位线，触发后仍可继续消耗（在快照中可见，用于告警）。
- **硬上限**：任何并发路径下都不得突破。登记（`Acquire`）的检查与计数在同一
  临界区内完成，并发争抢时成功数恰好等于剩余额度，不会允许超额。
- 单组超预算只影响自身：兄弟组的可用额度互不波及；某资源超量释放等异常
  仅钳制该资源计数，不影响其它资源计费。
- **软上限标记**：快照的每个资源视图直接给出 `soft_exceeded`（是否越过软上限）
  与 `soft_excess`（精确超出量，未越过为 0），调用方无需自行比较。
  判定口径为含后代的合计用量（借入部分同样计入），且与同一快照内的
  `aggregate`、`soft` 严格自洽：`soft_exceeded == (aggregate > soft)`、
  `soft_excess == max(0, aggregate - soft)`。越过软上限不改变继续消耗的规则。

### 用量登记与释放

- `Acquire(group, resource, amount)`：沿祖链逐层校验（祖先的合计用量含所有后代），
  全部通过后在同一临界区内记账。
- `Release(group, resource, amount)`：释放用量；释放超过已用量时返回错误并将
  该资源计数钳制为 0。

### 组间借用与归还

- 高优先级组（`priority` 数值更大）自有额度不足时，可向**优先级严格更低**、
  且有剩余额度的组借用；借出方不得与借入方互为祖先（避免祖链重复计数）。
- 借出方按 **(优先级升序, 名称升序)** 的确定顺序依次出让；总余量不足时
  整体失败，不产生任何记录。
- 借出量从借出方可用额度中预留（其自身与后代的新申请都会被压缩）。
- `ReclaimBorrows()` 在**同一临界区内**完成回收与超额归还：
  先按借用记录 ID 升序归还全部借出容量，再按（组名升序、资源名升序）的
  确定顺序**自动释放**各组超出其有效硬顶的合计用量（先释放本组自身用量，
  再按名称升序深度优先释放后代用量），无需调用方另行执行释放。
- 返回的**超额占用清单**与系统实际释放量一一对应（`Excess` 即释放量），
  也就是回收时点各组的超额明细；回收完成后任一组的合计用量不超过其
  有效硬顶，再次触发（无新占用时）返回空清单，多次触发结果可复现。
- 回收与并发新请求交错时，新请求只看到回收前或回收后的完整状态，
  一律按回缩后的剩余额度判定，不会在回收窗口内挤进超额登记。
  单个资源的释放异常只影响该资源自身的清单条目，不波及其它资源与其它组。
- 回收后已回到额度之内的组可按正常规则继续消耗（包括重新借用）。

### 原子重配置与重启恢复

- `Reconfigure(cfg)`：先整体校验（父子关系、比例、上下限、环检测），再原子
  落盘，最后整体切换生效指针；任一步失败都整体回退到上一个已提交版本，
  已登记用量按组名保留到新树。
- **配置隔离**：配置一旦被接受为已提交状态即被深拷贝，与调用方持有的原对象
  彻底隔离——调用方之后修改原对象不会改变生效中的限额；`Config()` 返回的
  同样是独立副本，修改副本不影响系统状态。生效中的限额只受显式提交动作影响。
- **版本号**：由系统强制维护，随每次成功提交严格递增。提交版本号小于等于
  当前已提交版本（重复或回退）一律被拒绝，旧配置保持完整生效；因此查询结果
  中的版本号唯一对应一次成功提交的内容。重启后从最近一次已提交版本继续递增。
- 持久化通过 `Store` 接口抽象；`FileStore` 采用「写临时文件 + fsync + rename」
  保证落盘本身也是原子的。
- 服务重启时从 `Store` 加载**最近一次已提交**版本恢复；未提交的中间改动
  不会落盘，也就不会被当作有效配置。

### 自洽快照查询

- `Snapshot(group)` 返回该组及全部后代在某一时间点的自洽快照
  （自身用量、含后代合计、有效软/硬顶、借入/借出、剩余量、软上限标记），
  快照在同一临界区内构造，高并发读写下结果可复现。

## 配置项

```jsonc
{
  "version": 2,                 // 配置版本号，必须严格大于当前已提交版本
  "groups": {
    "root": {                   // 恰好一个根组（parent 为空）
      "name": "root",
      "parent": "",
      "priority": 0,
      "share_ratio": 1,         // 根组忽略
      "quotas": {
        "cpu": { "soft": 80, "hard": 100 }   // soft <= hard，均 >= 0
      }
    },
    "team-a": {
      "name": "team-a",
      "parent": "root",
      "priority": 10,           // 数值越大优先级越高，决定借用资格与顺序
      "share_ratio": 0.5,       // 分得父组有效额度的比例，(0,1]
      "quotas": {               // 可选：收紧继承份额；缺省资源整体继承
        "cpu": { "soft": 30, "hard": 40 }
      }
    }
  }
}
```

校验规则：恰好一个根、父引用必须存在、无环、`share_ratio ∈ (0,1]`（非根）、
`0 <= soft <= hard`、组名非空且与 map 键一致。任何一项不合法则整份配置被拒绝。

## API 一览

| 方法 | 语义 |
| --- | --- |
| `NewManager(initial, store)` | 创建管理器；store 有已提交版本时从中恢复 |
| `Acquire(group, res, amount)` | 登记用量；不足时按规则尝试借用 |
| `Release(group, res, amount)` | 释放用量；超量释放报错并钳制该资源 |
| `Reconfigure(cfg)` | 原子重配置；版本重复/回退或校验失败整体回退 |
| `ReclaimBorrows()` | 回收借出容量并自动释放超额占用，返回与实际释放量一一对应的清单 |
| `Snapshot(group)` | 组及后代的自洽快照（含软上限标记） |
| `Config()` / `Borrows()` | 当前生效配置 / 当前借用记录（独立副本） |

## 测试

```sh
go test -count=1 -v ./...   # 全部测试（详细输出）
go test -race ./...         # 含并发竞态检测
go vet ./...                # 静态检查，应无告警
```

覆盖场景：继承与份额收敛、借用与归还（确定顺序、回收动作内自动归还超额占用、
清单与释放量一一对应、多次回收可复现、回收与并发申请交错）、并发登记与释放
（无计数丢失/重复扣减/超额）、硬软上限（软上限标记与用量自洽、借入计入判定）、
单组隔离、配置隔离（外部修改原对象/查询副本不影响系统）、版本号（重复与倒退
被拒绝、重启后继续递增）、重配置回退（非法配置与持久化失败）、
重启恢复与未提交改动丢弃。
