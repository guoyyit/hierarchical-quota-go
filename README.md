# hierarchical-quota-go

分层资源配额控制：将工作负载组织为可嵌套的配额组，支持组内与父子组之间
传递额度、跨组借用余量与故障恢复（原子重配置 + 重启恢复）。

## 核心概念

### 配额树与继承

- 配置为一棵树：恰好一个根组，其余组通过 `parent` 挂接，不允许成环。
- 子组按 `share_ratio`（取值 `(0,1]`）从父组的**有效额度**中分得份额：
  `有效硬顶 = min(自身 hard, 父组有效 hard × share_ratio)`，
  未配置的资源整体继承父组份额；软顶同理且不超过硬顶。
- 父组上调/下调额度后，子组的有效额度在重配置提交的同一时刻整体收敛到新预算。
- 任一时刻生效的限额是某个**已提交配置的完整快照**：配置以原子指针整体切换，
  进行中的消耗判定始终与某一个单一版本保持一致，不存在半更新或字段级混合。

### 硬上限与软上限

- **软上限**：水位线，触发后仍可继续消耗。快照中除给出数值外，直接提供两个
  可读字段，调用方无需自行比较：
  - `soft_exceeded`：该组（含后代合计用量 `aggregate`）是否已越过软上限，
    严格满足 `soft_exceeded == (aggregate > soft)`；
  - `soft_overflow`：越过后的精确超出量（`aggregate - soft`），未越过时为 `0`。

  标记与同一快照内的 `aggregate`/`soft` 取自同一临界区，任何时刻都自洽，
  不会出现「用量已越过而标记未置位」或反之。通过借用获得的额外用量计入
  `aggregate`，因此同样参与软上限判定；越过软上限不改变继续消耗的规则，
  硬上限在并发路径下依旧不可突破。新增字段不改变既有字段的名称、含义与取值，
  旧调用方无需迁移。
- **硬上限**：任何并发路径下都不得突破。登记（`Acquire`）的检查与计数在同一
  临界区内完成，并发争抢时成功数恰好等于剩余额度，不会允许超额。
- 单组超预算只影响自身：兄弟组的可用额度互不波及；某资源超量释放等异常
  仅钳制该资源计数，不影响其它资源计费。

### 用量登记与释放

- `Acquire(group, resource, amount)`：沿祖链逐层校验（祖先的合计用量含所有后代），
  全部通过后在同一临界区内记账。
- `Release(group, resource, amount)`：释放用量；释放超过已用量时返回错误并将
  该资源计数钳制为 0。

### 组间借用与归还

- 高优先级组（`priority` 数值更大）自有额度不足时，可向**优先级严格更低**、
  且有剩余额度的组借用；借出方不得与借入方互为祖先（避免祖链重复计数）。
- 借出方按 **(优先级升序, 名称升序)** 的确定顺序依次出让；总余量不足时
  整体失败，不产生任何记录。
- 借出量从借出方可用额度中预留（其自身与后代的新申请都会被压缩）。
- `ReclaimBorrows()` 在**同一个回收动作**内完成「撤销借用登记 + 自动归还超额」，
  调用方无需再另行释放：
  1. 先按借用记录 ID 升序撤销全部借出登记，借出方额度立即恢复；
  2. 再按「组名升序、资源名升序、子树后序（叶子用量优先、本组最后）」的
     确定顺序，把每个组超出其有效硬上限的合计用量自动从其自身/后代的
     已登记用量中扣减，直到合计用量不超过有效硬上限；
  3. 返回**超额占用清单**：每个发生实际扣减的（组, 资源）一条
     `OverOccupancy{Group, Resource, Excess, Released}`。`Excess` 是回收时点
     该组超出其有效硬上限的量，`Released` 是系统实际归还的量；同一组所有
     叶子项的 `Released` 之和恰等于其 `Excess`，一一对应。
- 回收完成后任一组的合计用量都不超过其有效硬上限；同一份容量不会再被
  借出方与借入组账面同时占用。回收与新 `Acquire` 在同一互斥临界区内交错，
  回收窗口内的新请求一律按回缩后的剩余额度判定，无法挤进旧的超额登记
  （自身额度不足时走全新借用流程，受相同硬顶约束）。
- 多次触发回收的结果确定可复现；第二次回收在无新占用时返回空清单且账面不变。
- 某一资源在自动归还时出现异常（通过 `WithReclaimHook` 注册的通知回调返回
  错误），只记录在对应清单项的 `ReclaimError` 中：账面归还照常完成，
  不影响其它资源的记账，也不波及其它组的额度。

### 原子重配置与重启恢复

- **配置隔离**：配置一旦被系统接受为已提交状态，就与调用方的原对象彻底隔离
  （系统保存独立深拷贝）。提交后调用方继续修改原配置对象，不影响正在生效的
  限额；`Config()` 查询同样返回独立副本，修改副本不改变系统状态。生效中的
  限额只受显式 `Reconfigure` 提交影响。
- **版本号自动维护**：版本号由系统分配并随每次成功提交严格递增，规则为
  `新版本号 == 当前已提交版本号 + 1`。
  - 首次提交（`NewManager`）一律分配版本 `1`，与初始对象里填写的数值无关；
  - 重复版本号、回退版本号或跳号的提交都被拒绝（错误包装
    `quota.ErrVersionConflict`），被拒绝时旧配置完整生效，且不会落盘；
  - 查询结果中的版本号唯一对应一次成功提交的内容；
  - 服务重启后从最近一次已提交版本继续递增（已到 v3，则下一次必须是 v4），
    不会出现重复或回退；
  - 未提交的中间改动（校验失败、版本冲突、落盘失败）在任何情况下都不进入
    生效配置，也不写入持久化存储。
- `Reconfigure(cfg)`：先整体校验（父子关系、比例、上下限、环检测），再原子
  校验版本号、原子落盘，最后整体切换生效指针；任一步失败都整体回退到上一个
  已提交版本，已登记用量按组名保留到新树。
- 持久化通过 `Store` 接口抽象；`FileStore` 采用「写临时文件 + fsync + rename」
  保证落盘本身也是原子的。
- 服务重启时从 `Store` 加载**最近一次已提交**版本恢复；未提交的中间改动
  不会落盘，也就不会被当作有效配置。

### 自洽快照查询

- `Snapshot(group)` 返回该组及全部后代在某一时间点的自洽快照
  （自身用量、含后代合计、有效软/硬顶、软上限越限标记与超出量、
  借入/借出、剩余量），
  快照在同一临界区内构造，高并发读写下结果可复现。

## 配置项

```jsonc
{
  "version": 2,                 // 版本号由系统自动维护：首次=1，此后必须=当前+1
  "groups": {
    "root": {                   // 恰好一个根组（parent 为空）
      "name": "root",
      "parent": "",
      "priority": 0,
      "share_ratio": 1,         // 根组忽略
      "quotas": {
        "cpu": { "soft": 80, "hard": 100 }   // soft <= hard，均 >= 0
      }
    },
    "team-a": {
      "name": "team-a",
      "parent": "root",
      "priority": 10,           // 数值越大优先级越高，决定借用资格与顺序
      "share_ratio": 0.5,       // 分得父组有效额度的比例，(0,1]
      "quotas": {               // 可选：收紧继承份额；缺省资源整体继承
        "cpu": { "soft": 30, "hard": 40 }
      }
    }
  }
}
```

校验规则：恰好一个根、父引用必须存在、无环、`share_ratio ∈ (0,1]`（非根）、
`0 <= soft <= hard`、组名非空且与 map 键一致。任何一项不合法则整份配置被拒绝。

## API 一览

| 方法 | 语义 |
| --- | --- |
| `NewManager(initial, store)` | 创建管理器；store 有已提交版本时从中恢复 |
| `Acquire(group, res, amount)` | 登记用量；不足时按规则尝试借用 |
| `Release(group, res, amount)` | 释放用量；超量释放报错并钳制该资源 |
| `Reconfigure(cfg)` | 原子重配置，失败整体回退 |
| `ReclaimBorrows()` | 回收借出容量并在动作内自动归还超额，返回超额清单 |
| `Snapshot(group)` | 组及后代的自洽快照 |
| `Config()` / `Borrows()` | 当前生效配置 / 当前借用记录（均为独立只读副本） |
| `NewManager(initial, store, opts...)` | 可选 `WithReclaimHook`：注册逐（组, 资源）的自动归还通知 |

## 测试

```sh
go test -count=1 -v ./...   # 全部测试（详细）
go test -race ./...         # 含并发竞态检测
go vet ./...                # 静态检查
```

覆盖场景：

- 继承与份额收敛、硬/软上限与单组隔离；
- 借用与回收：回收动作内自动归还超额（含子树分摊）、归还量与清单一一对应、
  回收与并发申请交错时硬顶不破、多次回收的确定性与可复现性、单资源归还异常
  不波及其它资源与其它组；
- 软上限：`soft_exceeded`/`soft_overflow` 与同快照用量自洽、借用用量计入、
  越软顶后硬顶仍不可破；
- 配置隔离：提交后修改原对象不影响生效配置、查询副本独立；
- 版本号：重复/回退/跳号提交被拒绝（旧配置完整生效且不落盘）、首版分配为 1、
  重启后从最近版本继续递增；
- 并发登记与释放无计数丢失/重复扣减/超额；
- 重配置回退（非法配置与持久化失败）、重启恢复与未提交改动丢弃。
